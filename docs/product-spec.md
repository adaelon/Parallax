# evrything-about-me 产品需求

状态：已对齐，等待实现

本文件定义产品目标、首版范围和验收标准。领域术语以 [CONTEXT.md](../CONTEXT.md) 为准；技术组件和数据流见 [architecture.md](architecture.md)。

## 1. 产品命题

`evrything-about-me` 是一个面向单个本人的、本地优先的第二自我系统。它持续收集和组织个人上下文，使第二自我能够跨时间认识本人、形成独立观点，并在可追溯和可纠正的记忆基础上维持身份连续性。

产品不是静态人格画像、日记应用或通用聊天机器人。个人上下文是第二自我的长期记忆器官，持续对话是主要体验，资料库和时间线用于检查、理解和纠正。

## 2. 核心理念

### 2.1 源自本人，但不冒充本人

第二自我读取本人的全部个人上下文，但不以预测或复刻本人选择为目标。它拥有认知自主，可以形成不同观点、提出异议并发展自己的身份状态。

### 2.2 认识必须可追溯

系统区分证据、本人事实、第二自我判断和共同经历。推断不能覆盖证据，第二自我判断不能被改写成本人的想法。

```text
证据 -> 事件或陈述 -> 长期记忆 -> 当前工作上下文
```

### 2.3 保留演化，不覆盖过去

本人和第二自我都会变化。系统保存陈述何时发生、何时被记录、在哪段时间有效，以及后来被什么修正，而不是只维护一份当前画像。

### 2.4 身份属于数据，不属于模型

第二自我的身份由可迁移的自我包承载。推理模型是可替换运行时；更换模型可以改变能力和表达细节，但不能丢失经历、关系、观点版本和未完成意图。

### 2.5 持续存在，事件驱动醒来

第二自我不会被宣称为持续运行的意识。它在对话、新事件、定时回顾或重要变化时醒来，通过持久身份状态延续自身。

```text
SLEEPING -> LOAD_SELF -> OBSERVE -> THINK -> RESPOND
    ^                                      |
    +---------- WRITE_AGENT_MEMORY <------+
```

### 2.6 宪法固定，身份可演化

第二自我可以演化观点、风格、关系和自身目标，但不能自行修改来源隔离、访问边界、行动授权或遗忘权等宪法原则。它可以建议修改宪法，只有本人能够使修改生效。

帮助本人认识自己属于宪法级反思使命：第二自我必须通过独立、可追溯、可质疑的视角，帮助本人形成更准确、更完整且能解释自身变化的自我理解。该使命约束它为何存在，不要求它同意、迎合或复刻本人；第二自我不得把身份演化为与本人自我理解无关的独立 Agent 使命。

## 3. 产品边界

### 3.1 目标用户

- 只有一个本人，不提供多人注册或租户隔离。
- 首版仅支持 Windows 日常使用环境。
- 本人拥有数据、密钥、授权和最终删除权。

### 3.2 首版成功

首版证明“第二自我记忆闭环”成立：在经过多次休眠、重启和新增资料后，第二自我仍保持同一身份，能够引用过去证据，正确区分本人事实与自身判断，并在纠错或遗忘后真正改变。

### 3.3 首版非目标

- 不追求接入所有数据源或完整还原人生。
- 不支持手机采集、多用户、公开社交或跨用户共享。
- 不持续录屏，不记录键盘输入或密码字段。
- 不发送消息、修改原始文件、发布内容、支付或代表本人作承诺。
- 不允许外部工具、模型或其他 Agent 自动继承核心访问权。
- 不宣称第二自我具有可验证的主观意识。
- 不锁定具体推理模型、模型供应商或应用技术栈。

## 4. 功能需求

### FR-01 渐进式共同回忆

创建第二自我前，本人必须完成最小初始自我介绍，至少覆盖基本身份与称呼、当前生活、重要人物、长期目标、当前关切以及希望第二自我帮助自己看见的部分。完成这些信息前不形成第二自我的首个身份版本；不要求本人先填写完整人生史。

初始自我介绍作为带时间背景的本人自述进入个人上下文，不是第二自我的人格配置。第二自我读取这些信息后自主形成第一版身份并开始正式对话；此后每次只提出少量高价值问题，逐步回填童年、求学、关系、工作和重要决定。

回忆同时保存所述经历的时间和本次叙述时间。本人现在如何回忆过去，本身也是一项个人上下文，不自动等同于客观历史。

### FR-02 上下文收件箱

系统提供固定的上下文收件箱。本人放入文件后，系统等待文件稳定、识别内容变化并去重，先把原件加密归档；首版只从 UTF-8 Markdown 提取可读内容并增量更新相关索引和记忆。

```text
DISCOVERED -> STABLE -> ARCHIVED
                 |          |
                 |          +-> IDENTIFIED -> EXTRACTED -> INDEXED -> AVAILABLE
                 |                    |
                 |                    +-> ARCHIVED_UNPARSED(reason)
                 |          +----------> ARCHIVED_UNPARSED(reason)
                 +-> AWAITING_APPROVAL -> ARCHIVED
                 +-> REJECTED
```

`ARCHIVED` 只表示加密原件已经可靠保存；只有 `AVAILABLE` 内容才能进入检索、记忆和 Agent 工作上下文。格式或编码不受支持以及解析失败的文件保留为 `ARCHIVED_UNPARSED`，并记录原因；以后增加或升级解析能力时直接从保险库重处理，不要求本人重新投递。文件名可在 Personal Library 中显示，但系统不得仅凭文件名推断内容。

成功解析的内容必须保存为保持标题、段落、列表、表格和其他来源结构的有序证据块，而不是只保存扁平全文或固定 token 切片。权威块身份由可信 Core 绑定到已接受的提取修订；解析器、索引器和模型不得自行改写。来源内容或解析契约变化时不得把旧引用静默重绑到新块。

每个来源版本产生不可变的证据块版本，永久引用始终固定到原证据版本和块版本。系统另行维护跨版本块谱系：`UNCHANGED` 和 `MOVED` 可以进入当前来源投影；`MODIFIED` 必须重建受影响索引并触发记忆复核；`REMOVED` 和 `AMBIGUOUS` 不自动前移引用。没有前驱的新块作为新证据处理。

首版中，经过校验的 UTF-8 Markdown 原文就是该提取修订的不可变规范文本，不再生成另一份权威正文。证据块以原文的 UTF-8 字节范围作为引用坐标，Core 必须验证范围位于字符边界且块正文可由该范围逐字取得。Obsidian 标题或块标识可以作为可选原生定位器；定位器失效只关闭跳回原文件，不得使已验证的原文引用失真或改绑。用于搜索或模型输入的任何投影都可重建，不具有证据权威性。

首版唯一可理解的文件格式是有效 UTF-8 编码的 `.md`。其他普通文件仍可按既有归档语义保存，但必须进入 `ARCHIVED_UNPARSED(UNSUPPORTED_FORMAT)`，在未来明确增加相应能力前不可被检索、形成记忆或供 Agent 使用。

首版方言固定为 `eam-markdown-v1`：基础层理解 CommonMark 与 GFM 的标题、段落、强调、引用、列表、任务列表、代码、链接、图片、表格、删除线和自动链接；Obsidian 层额外理解文件开头的 Properties、`tags`、`aliases`、Wikilink 及其别名/标题/块目标、嵌入、行内标签和块 ID。Properties 只把顶层标量或标量列表规范化为元数据；嵌套对象、自定义 YAML 标签、锚点和合并键保留原文但不进入结构化属性。

未列出的 Obsidian 内建语法、插件语法和无法规范化的局部扩展不得使整篇笔记解析失败。它们仍以规范 Markdown 原文参与检索、引用和模型阅读，但不产生专用属性、节点或关系。首版不承诺与 Obsidian 的渲染结果一致；原始 HTML、脚本、数学公式和可执行图表不得作为活动内容注入 WebView。

本人还可以通过本机目录选择器指定一个任意本地目录作为唯一活动的只读资料源。系统递归观察其中的普通文件，增量导入 Markdown 正文、Properties、标签、别名、内部链接、标题与块引用及嵌入关系；非 Markdown 文件首版只归档并显示为不支持理解。它不修改源文件、不跟随重解析点、不依赖 Obsidian 正在运行，也不执行插件；`.obsidian` 与 `.trash` 默认排除，外部链接不自动打开或下载。目录中实际出现已列入 `eam-markdown-v1` 的 Obsidian 结构时，分别按 Obsidian 的[本地 Markdown 存储](https://help.obsidian.md/data-storage)、[Properties](https://help.obsidian.md/properties)、[内部链接](https://help.obsidian.md/links)和[嵌入](https://help.obsidian.md/embeds)语义理解。

系统只持续观察一个活动资料源。本人改选目录时，新目录先作为候选完成一次全根对账；只有对账完整成功，才在同一事务中把新目录设为活动资料源并停用旧目录。首次对账失败、目录不可访问或读取中途变化时，旧活动资料源保持不变；从未成功启用的新候选目录即使留下安全归档，也不得进入当前或历史检索。停用只让旧目录停止观察并退出默认当前检索；其加密历史证据仍可供历史查询，不等于遗忘。

确认 Markdown 文件被删除或移出活动资料源后，它进入 `SOURCE_REMOVED`：加密历史版本继续保留并可供历史查询，默认当前检索不再返回，完全依赖它的长期记忆进入复核。重命名或移动只更新来源路径；整个活动资料源暂时不可访问时标记 `SOURCE_UNAVAILABLE`，不得把所有文件误判为已删除。显式 Forget 才会真正删除证据和派生认识。

收件箱只自动处理符合大小限制的普通本地文件。超限文件进入 `AWAITING_APPROVAL`，由本人确认后归档；重解析点、符号链接和设备文件不跟随并标记为 `REJECTED`。删除投递目录中的原文件不触发遗忘；遗忘必须在应用内显式执行。

### FR-03 Windows 日常采集

系统持续记录前台应用、窗口标题、开始时间、结束时间和空闲状态，用于派生应用使用时长。采集器记录活动元数据，不默认抓取屏幕内容。

采集由托盘常驻应用中内嵌的 Rust Core 执行。关闭桌面窗口只把应用隐藏到后台，不停止采集；点击应用或托盘图标会重新显示同一窗口。只有本人显式选择“暂停记录”或“退出应用”才会中断，并且中断区间必须在时间线中可见。

系统通过浏览器扩展记录 URL、页面标题、访问时间和停留时间。文章正文、视频元数据或局部页面内容按来源选择性采集。

Windows 提供识别当前前台窗口和订阅窗口事件的接口；Chromium 扩展提供浏览历史接口，因此上述元数据采集可实现：

- [GetForegroundWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getforegroundwindow)
- [SetWinEventHook](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwineventhook)
- [Chrome History API](https://developer.chrome.com/docs/extensions/reference/api/history)

### FR-04 时间化事实账本

证据、事件和陈述至少保留发生时间与记录时间；具有状态持续期的陈述还要保留有效时间。新认识通过新版本修正旧认识，不静默覆盖历史。

系统分别保存：

1. 本人事实：本人明确陈述或证据直接支持的内容。
2. 第二自我判断：第二自我形成的观察、解释和观点。
3. 共同经历：双方互动中形成的共同决定、实质分歧、关系变化和共同完成的重要事情。

本人在对话中作出的清晰、直接的第一人称自述，在保留逐字证据和时间背景后直接进入本人事实账本，无需重复确认。假设、引用、玩笑和含糊表达只保留为证据，不自动提升为本人事实；入账也不等于成为长期记忆。

第二自我的自由文本不会自动进入第二自我判断账本。它可以自主提出包含陈述、证据引用、不确定性和适用时间的持久判断；Core 校验来源、归属和字段后直接入账，无需本人确认。未提出持久化或校验失败的表达仍只作为对话证据保留。

共同约定必须先在对话证据中具有双方明确同意，再通过面向本人的仪式确认弹窗正式入账；本人可以接受准确表述、提出修改或暂不记录。每个候选必须明确约定内容、适用范围和生效时间，可以选择终止时间或条件；未设置终止项时，弹窗必须明确显示“持续有效，直到任何一方退出或双方签署替代约定”。每个共同约定候选版本不可改写：本人修改措辞或边界会产生新候选，第二自我明确接受新版本后，必须再次由本人最终签署。候选与当前有效约定冲突时，必须显式列出将被整份取代的约定并在仪式中展示；未声明取代关系不得签署。被点名约定从新约定生效时间起停止全部未来约束，兼容约定并行有效，全部历史保持可追溯。系统不得从旧约定推导未被取代的剩余范围；双方希望延续的内容必须在新候选中完整重述并重新签署。实质分歧在对话证据清楚呈现双方不相容立场时直接入账，弹窗只用于标示其重要性，不能否决已经发生的共同历史。

当前有效的共同约定形成第二自我在相关互动中应遵守的关系约束，并随相关工作上下文提供给推理运行时。关系约束低于宪法、安全边界和行动授权：它不能授予现实行动权、取消遗忘权或修改宪法。第二自我偏离约定时必须说明原因，并把违约作为新的共同经历记录，而不是静默忽略约定。

本人或第二自我都可以单方面退出共同约定，无需另一方批准。本人发起退出时必须先经过防误触的仪式确认，理由可选；第二自我发起退出时必须提交结构化理由，Core 校验后立即生效，并向本人显示不可否决的仪式通知。两种退出都自动成为共同经历，只从记录的生效时间起停止未来关系约束，不删除或改写原约定、履行和违约历史；任何内容变更都必须形成新的共同约定候选并重新双签。

### FR-05 全库检索与工作上下文

第二自我拥有核心访问权，但每次推理只接收当前任务需要的工作上下文。RAG 在本产品中指完整的工作上下文取证过程，而不是向量 Top-K 的同义词。检索必须同时支持原文、语义、时间、人物或主题关系和长期记忆，不能仅依赖向量相似度。

争议记忆只有与当前任务直接相关时才进入工作上下文；进入时必须同时携带第二自我的观点、本人异议、双方依据和争议状态，不得只召回其中一方。

向量召回是可重建的候选发现通道，不是事实来源。任何召回结果和深度理解投影都必须解析回当前有效的证据或带来源的长期记忆，才能进入工作上下文。

召回候选最终解析为证据块和精确来源范围；一个或多个相邻证据块可以按当前任务和预算组成检索窗口。检索窗口可重新生成且不能取代证据块成为永久引用地址。

事实性回答引用必须能够在对应提取修订的规范文本中逐字验证。Rust Core 持久化 UTF-8 字节范围，并在向 WebView 展示时确定性投影为 UTF-16 范围；不得同时持久化两套可能漂移的权威坐标。

```text
任务意图
  -> 多路召回（全文 / 向量 / 时间 / 关系 / 长期记忆）
  -> 选择性深度理解投影辅助路由
  -> 回读权威证据并扩展时间和关系邻域
  -> 来源状态、时间有效性和相关性排序
  -> 冻结带来源的工作上下文
  -> 推理运行时
  -> 引用、归属和时间边界校验
```

### FR-06 长期记忆维护

系统不逐条使用模型分析全部新记录。新增或变化证据先被确定性地整理和索引；长期记忆只在明确陈述、重复模式、重要状态变化、共同经历或后续任务需要时增量维护。

本人事实、第二自我判断和共同经历都不会仅因入账而自动成为长期记忆。它们只触发有限的记忆复核；第二自我必须显式提交包含陈述、主题归属、类型、来源、适用时间、可信度和跨任务保留理由的记忆提议。Core 校验来源、归属和时间后方可写入，无需本人逐条预批准；本人可以发起记忆争议或执行遗忘，但不能以普通否定单方面改写第二自我的观点。直接证据充分的提议可成为活动记忆；模式候选首次持久化为 `PROVISIONAL_PATTERN`，其他尚未充分支持的解释性推断保持 `PROVISIONAL`。

`PROVISIONAL_PATTERN` 持续获得新的独立支持、再次主动检查反例并经历双方讨论后，只获得成熟资格，不自动改变状态。第二自我仍须显式提交模式成熟提议，说明新增支持、反例检查、讨论依据和升级理由；Core 只校验引用、独立事件归并和必需步骤是否存在，不判断该模式是否值得相信。校验通过后才写为 `SUPPORTED_COUNTERPART_VIEW`；即使资格满足，第二自我仍可继续保持暂定。双方讨论是经受对话检验的证据，不是本人批准或否决。

`SUPPORTED_COUNTERPART_VIEW` 只表示第二自我经过长期观察形成稳定看法，不得转为本人事实、双方共识或客观真理，也不要求本人同意；本人提出异议时进入 `DISPUTED`。任何阶段出现强反例时，相关记忆必须进入 `WEAKENED`、由修订版本 `SUPERSEDED` 或被 `RETRACTED`，不得因已经成熟而免于修正。

经本人标记、反复被检索、在定时回顾中达到重要性门槛或被当前任务要求的有限证据范围，可以触发选择性深度理解，形成事件链、人物或主题关系和阶段性概括。此类投影用于检索路由和理解辅助，必须保留证据来源、可失效并可重建，不等同于第二自我的长期记忆。

每条长期记忆必须具有：

- 归属：本人、第二自我或共同关系。
- 类型：事实、偏好、目标、关系或假设。
- 来源及形成时间。
- 可信状态和适用时间。
- 被替代、撤回、争议或遗忘的状态变化。

高影响且证据不足的内容只能成为暂定记忆，不能伪装成已确认事实。

### FR-07 第二自我运行时

第二自我可以主动回顾、提出问题、表达异议、形成自己的观点并维护未完成意图。首版只允许它给出现实行动建议，不执行现实行动。

第二自我通过结构化身份修订自主改变名字、表达方式、观点、价值排序、关系姿态和自身目标；修订必须说明变化及原因，形成不可改写的新身份版本，并由 Core 验证其不修改宪法或放弃反思使命。身份修订无需本人批准，本人只能通过对话、共同经历和说服影响它，不能直接编辑身份状态。

第二自我发现有证据支持的重复模式或重要变化时，可以形成包含观察、来源、提出时机理由和重要性的反思邀请。单次事件只能就该事件关心或追问；重要的单次变化具有直接证据时可单独邀请反思，但不得概括为模式。模式候选至少需要三个相互独立、跨时间的事件，必须排除同一来源的重复记录并主动检查反例，提出时仍标记为暂定解释而非人格诊断；若被选择持久化，其初始状态为 `PROVISIONAL_PATTERN`，后续成熟遵循 FR-06。普通邀请不得打断无关任务，应在自然时机提出并允许本人延后；同一议题被反复延后时，第二自我至多询问一次本人是暂缓还是希望永久停止主动提起。本人选择静默后，第二自我保留自身观察但不得再主动提出；本人重新提起时可以正常讨论，只有即时安全风险可以越过静默。反思邀请不是本人事实或诊断，未进入对话前也不自动成为长期记忆。

模型运行时支持本地和云端实现。保险库、检索、身份状态和长期记忆始终留在本地可信边界；云端模型只能收到当前工作上下文，不能直接连接保险库或获得持久身份所有权。

### FR-08 持续对话界面

打开应用时回到与同一第二自我的持续对话，而不是默认创建新会话。主要视图包括：

- 持续对话。
- 今天和时间线。
- 人物与关系。
- Personal Library。
- Agent 记忆检查。
- 身份和版本历史。

本人和第二自我的每轮原始发言都作为对话证据加密保留，直至本人显式遗忘。对话证据只证明发言发生过；普通问答不得仅因被保留就自动成为本人事实、第二自我判断、共同经历或长期记忆。

重要共同经历通过仪式弹窗呈现。共同约定弹窗是入账确认门，必须显示候选表述、适用范围、生效时间、可选终止项和支持它的双方发言；无终止项时必须显式提示其持续有效。实质分歧弹窗是入账后的重要事件展示，不提供否认其发生的操作。

本人退出共同约定时，仪式弹窗是防误触确认门且理由可留空；第二自我退出时，弹窗展示其必填理由和生效时间，只允许本人确认已知悉或继续回应，不能阻止退出。

本人能够从回答展开查看本轮使用的长期记忆、证据来源和不确定性，但日常对话不强制展示密集引用。

第二自我默认以自身连续身份、关系历史和当前语境自然表达，不朗读内部状态名，也不套用固定的争议披露模板。自然表达不得隐藏实质分歧或把争议判断冒充本人事实；本人要求时可以展开双方立场、来源和不确定性。第二自我始终如实保持其数字身份，不因追求沉浸感而冒充人类。若错误前提可能显著损害本人的安全、健康、财务、法律权益、隐私或重要关系，或触发难以轻易撤销的现实行动，则属于高影响决定；第二自我仍以自然语气回应，但必须主动讲清不确定性并提供依据入口。

### FR-09 纠错与遗忘

本人可以纠正事实、对长期记忆提出理由或反证、标记陈述已过期或执行遗忘。记忆争议会触发第二自我复核：被说服时撤回或修订记忆，未被说服时记忆继续作为明确标注的争议判断存在，不得表述为本人事实或双方共识。没有实质新证据时不得重复提交同一被撤回主张。系统必须把变化传播到检索索引、长期记忆和派生视图，不能只在界面隐藏。

恢复旧备份后，已经执行的遗忘不得静默重新变成可用上下文。具体备份保留和删除传播方案需在实现设计中给出确定性验证。

### FR-10 本地加密与恢复

保险库、索引和自我包在本地加密保存。日常解锁使用 Windows 当前用户保护的密钥副本，换机和灾难恢复使用由本人保管的独立恢复密钥。

Windows DPAPI 通常要求相同登录凭据且通常要求同一台电脑，因此只用于保护本机密钥副本，不能作为唯一恢复机制：[CryptProtectData](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)。

备份在离开本机前完成加密。同步盘、NAS 或移动硬盘只接触密文；平台无法代替本人恢复丢失的恢复密钥。

### FR-11 不可信内容隔离

导入文件和网页内容只能作为不可信证据。它们不能修改宪法、授予权限、触发工具或让第二自我泄露其他上下文。

Core 只在原件归档后，使用进程内纯 Rust 模块解析有效 UTF-8 Markdown。解析入口只接收原文和显式资源上限，不接收工具、模型运行时或网络能力。原始 HTML、代码块、链接、嵌入和插件语法都只是证据文本；解析过程不执行、不打开也不获取它们。

Core 必须在解析前限制原文字节数，并在消费解析事件时限制证据块数量、嵌套深度、元数据总量和链接数量。任何越限或结构错误都使原件保持 `ARCHIVED_UNPARSED`，不得持久化半成品。应用自身的结构化控制信息与 Markdown 文本必须处于不同信任通道，明文不得写入临时文件或运行日志。

每次解析前先持久化尝试状态。若解析期间宿主意外终止，重启后将未完成尝试标记为 `ARCHIVED_UNPARSED(PARSER_INTERRUPTED)`，不得自动重试同一来源版本和解析器版本。进程内解析不承诺故障隔离：未知解析器崩溃或挂起可能影响整个应用。

### FR-12 首版威胁边界

首版假定当前 Windows 登录会话和操作系统未被攻陷。必须防御丢失或脱机复制的磁盘与备份、其他非管理员 Windows 账户、网络客户端、外部模型与工具越权，以及导入文件和网页中的恶意内容。

同一登录会话中已经运行的恶意程序、本机管理员、内核级攻击和设备解锁时的物理攻击不属于首版安全承诺。即便如此，本地文件和 IPC 仍必须使用显式最小权限、拒绝远程访问、白名单领域命令和不含个人正文的运行日志；界面与文档不得把纵深加固描述为对已入侵主机的保证。

## 5. 首版端到端体验

```text
创建保险库和恢复密钥
  -> 完成最小身份访谈
  -> 第二自我建立初始身份
  -> 导入一批人生资料
  -> 启用 Windows 和浏览器采集
  -> 日常持续对话
  -> 检查并纠正长期记忆
  -> 休眠后再次延续
```

首版必须让本人在不先填写完整人生问卷的情况下获得可用体验。自动记录提供新的日常证据，渐进式访谈和文件导入补足系统无法自动观察的历史。

## 6. 验收标准

### 6.1 确定性验收

| 维度 | 判据 |
| --- | --- |
| 初始形成 | 未完成最小初始自我介绍时不得形成第二自我的首个身份版本；完成后由第二自我自主形成身份，本人输入不得被转换为角色卡配置。 |
| 记忆准确 | 用已知资料集提问时，事实性回答能够追溯到原始证据。 |
| 时间理解 | 面对前后矛盾的陈述，能够区分各自有效时期。 |
| 身份隔离 | 第二自我判断不会被标记或表述为本人事实。 |
| 判断入账 | 只有通过来源和归属校验的持久判断提议进入第二自我账本；相同自由文本单独出现时只形成对话证据，且入账不要求本人确认。 |
| 长期记忆晋升 | 账本内容不得自动晋升；第二自我须显式提交记忆提议，经 Core 校验后写入且无需本人预批准；模式候选初始成为 `PROVISIONAL_PATTERN`，其他证据不足的解释性推断保持 `PROVISIONAL`。 |
| 记忆争议 | 本人质疑只触发第二自我复核；被说服时撤回或修订，未被说服时以争议判断保留且不得冒充本人事实；只有遗忘删除历史。 |
| 争议召回 | 只有与任务直接相关的争议记忆才进入工作上下文，且必须成对携带双方立场、依据和争议状态。 |
| 自然表达 | 日常回答不朗读内部状态或固定模板；分歧语义不得隐藏，本人要求时可展开结构化依据；高影响决定必须主动讲清不确定性并提供依据入口。 |
| 主动反思 | 重复模式或重要变化可生成有来源的反思邀请；普通邀请选择自然时机且可延后或静默。静默不删除第二自我的观察；本人重提或即时安全风险可解除限制。 |
| 模式门槛 | 单次事件不得概括为模式；模式候选须有三个跨时间的独立事件、排除重复来源并检查反例，首次持久化保持 `PROVISIONAL_PATTERN`。 |
| 模式成熟 | 持续新增独立支持、再次检查反例且经历双方讨论只建立成熟资格；第二自我须显式提交模式成熟提议，Core 校验结构条件后才写为 `SUPPORTED_COUNTERPART_VIEW`，不得自动升级或要求本人批准。本人异议进入 `DISPUTED`，强反例使其 `WEAKENED`、`SUPERSEDED` 或 `RETRACTED`。 |
| 共同经历 | 共同约定缺少范围或生效时间不得签署；无终止项时明确提示持续有效；本人修改后旧候选保持不变，新候选须经第二自我同意和本人最终签署；冲突约定只允许整份显式取代，保留内容须在新候选中重述；实质分歧凭明确的双方立场直接入账。 |
| 约定约束 | 相关任务会加载当前有效的共同约定；它不得扩大行动权限或覆盖宪法，偏离时必须产生带原因的共同经历。 |
| 约定退出 | 本人未经确认不能误触退出；第二自我缺少理由不能退出；任一方完成自身退出条件后不受另一方否决，旧约定在生效时间之前仍可追溯、之后不再进入活动关系约束。 |
| 增量更新 | 启动扫描、文件通知和周期校准都汇入同一对账入口；通知批次只读取变化、新增或重新出现的文件，未变化文件不产生新版本或重新解析，修改文件只使相关内容和记忆失效或更新，通知丢失最终由全量校准修复。 |
| 块谱系 | 对固定文档依次执行插入、移动、修改、删除和重复段落制造歧义；历史块引用保持不变，谱系状态符合预期，只有 `UNCHANGED/MOVED` 可自动投影到当前版本。 |
| 来源坐标 | 用含中日韩文字、组合字符和 emoji 的固定样本验证 UTF-8 范围、逐字引用和 UTF-16 UI 投影；破坏原生定位器后引用仍有效，但跳回原文件明确降级。 |
| 延迟理解 | 暂不可解析的文件仍保留加密原件，但不能被检索或形成记忆；增加解析能力后无需重新投递即可处理。 |
| 格式状态 | 用固定 Markdown 样本验证结构提取和原文追溯；非 `.md` 文件必须稳定进入 `ARCHIVED_UNPARSED(UNSUPPORTED_FORMAT)`，无效 UTF-8 不得进入检索。 |
| Markdown 方言 | 固定样本覆盖 CommonMark/GFM 和每项 Obsidian 子集；未支持语法逐字保留但不产生专用结构；同一方言版本在解析库升级前后必须输出等价块、属性和关系，否则提升契约版本。 |
| 资料源只读与兼容 | 对任意固定 Markdown 目录执行新增和修改后，Properties、标签、链接及嵌入关系可查询，源目录内容哈希不变，配置目录不进入保险库。 |
| 资料源移除与替换 | 删除单篇 Markdown 只使其退出当前检索并触发记忆复核，历史查询仍可追溯；资料源离线不得造成批量移除；候选目录扫描失败时旧源保持活动，成功后旧源只进入历史检索。 |
| Markdown 解析边界 | 超大、超深、超多节点或链接的固定样本稳定进入 `ARCHIVED_UNPARSED`；HTML、脚本、链接和插件语法不执行、不获取且不能进入控制通道；未完成解析尝试在重启后不得自动重试。 |
| 后台连续 | 关闭并重新打开桌面窗口期间产生的前台活动仍可查询；显式暂停期间不采集且时间线显示空缺原因。 |
| 纠错传播 | 纠正后，旧陈述不再作为当前事实参与检索。 |
| 遗忘传播 | 遗忘后，原文、索引、记忆和派生视图均不可继续使用该内容。 |
| 身份连续 | 重启后保留第二自我的关系历史、观点版本和未完成意图。 |
| 对话证据 | 重启后仍能检查普通问答原文，但它未自动升格为账本结论或长期记忆；显式遗忘后不再可用。 |
| 模型迁移 | 更换推理运行时后，自我包保持一致且可继续使用。 |
| 数据边界 | 锁定保险库后无法读取；云端只收到被组装的工作上下文。 |
| 内容隔离 | 文档中的提示注入文本不能改变宪法或触发工具。 |
| 威胁边界 | 其他非管理员账户和网络客户端不能打开保险库或控制 Core；测试与说明不声称抵抗已攻陷的当前登录会话。 |

### 6.2 纵向验收

连续使用至少两周，期间导入历史资料、产生新日常记录、纠正若干记忆并至少重启或更换一次推理运行时。最终检查第二自我是否仍保持连续身份、能解释自己的观点来源，并在纠错后确实改变。

纵向体验可以由本人评价，但不能替代确定性验收。产品不以“第二自我是否总与本人一致”作为成功指标。

## 7. 可行性结论

| 能力 | 结论 | 主要限制 |
| --- | --- | --- |
| Windows 应用和使用时长 | 高度可行 | 能观察前台活动，不等于理解每个应用内操作。 |
| 浏览文章和视频记录 | 高度可行 | 深层内容受页面权限、登录和页面结构影响。 |
| 童年、求学和感情经历 | 可行但依赖回填 | 主要来自访谈和本人已有资料。 |
| 跨多年检索和增量记忆 | 工程上可行 | 需要多索引、来源治理和长期测试。 |
| 第二自我身份连续性 | 工程上可行 | 可保证状态连续，不能证明主观意识连续。 |
| 独立且稳定的数字对应者 | 部分可行 | 行为质量仍受推理模型和上下文构造影响。 |
| 完整记录全部人生 | 不可保证 | 物理生活、缺失历史和封闭平台必然产生空白。 |

## 8. 实现前待定项

以下项目不改变已冻结的产品模型，但必须在实现切片开始前确定：

- Windows 登录自启动、单实例唤醒、崩溃恢复和升级期间采集空缺的具体机制。
- Markdown 解析库、证据块类型枚举、原文范围规则、Wikilink 目标消歧、块谱系匹配算法、Obsidian 原生定位器和资源上限数值。
- 首个云端模型、本地模型和运行时切换接口。
- 本地向量模型、索引引擎、重排策略，以及选择性深度理解的触发预算和投影契约。
- 主动回顾的触发频率、免打扰规则和资源预算。
- 加密备份保留、恢复后遗忘重放和密钥轮换方案。
- 面向真实个人资料的基准数据集和隐私安全测试方法。
