# 正式对话以完整第二自我状态为就绪门禁

**决策**：仅在首个身份与首个自我包原子持久化后开放正式对话；普通运行时请求必须携带当前身份和自我包状态。

**否决**：
- 只在前端隐藏输入框：旁路 command 或状态漂移仍可产生无身份回答。
- 保留可选身份并降级为通用助手：会把“第二自我”退化为提示词角色扮演。
- 用首条普通消息懒创建身份：会混淆初始自我介绍、身份形成与正式关系历史。

**命门**：创建请求与正式对话请求使用不同类型；旧回复保留为未绑定身份的证据而不追溯归属，主体状态不完整时失败关闭。
**何时回头**：产品需要明确标识且不持久化身份的预创建体验时，以独立模式重新决策。
