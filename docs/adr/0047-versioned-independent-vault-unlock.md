# 保险库采用版本化且相互独立的双解锁载体

**决策**: 恢复密钥用 Bech32m；两种独立封装原子写入版本化元数据。

**否决**:
- 普通口令加 KDF：增加弱口令与参数迁移风险，且不需要牺牲 256-bit 熵。
- 两种封装分成两个文件：首次初始化无法原子提交，崩溃可能只留下半套密钥材料。
- S03 同时实现轮换：会把恢复格式冻结与历史密文重写混成一个切片。

**命门**: `bundle.meta` 只含版本、随机参数和两份密文；恢复路径不得读取或依赖 DPAPI 字段。
**何时回头**: S30 定义备份恢复与轮换，或 Bech32m/HKDF/XChaCha20-Poly1305 出现实质兼容性或安全问题时。
